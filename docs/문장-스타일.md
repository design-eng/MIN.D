## 1. 원칙

1. **한자어·외래어보다 쉬운 우리말.** 학부 3학년이 소리 내어 읽었을 때
   걸리지 않는 말을 고른다. 전문용어처럼 보이려고 쓰는 말은 전부 뺀다.
2. **단정 대신 설명.** "~해야 합니다", "~입니다"로 밀어붙이지 않고
   "~하면 됩니다", "~해 봅니다", "~할 수 있다"로 여지를 둔다.
3. **명령형 제목을 피한다.** 장표 제목은 무엇을 다루는지 알려 주는 말이지
   지시가 아니다. (`차별화 포인트 도출하기` → `나만의 강점 찾기`)
4. **학생을 우리 안에 둔다.** `전공 특성상` → `우리 전공은`.
5. **굵은 서체를 남용하지 않는다.** 디스플레이 타입은 Pretendard SemiBold 까지다.
   Black 은 글자 속이 막혀 투사 화면에서 오히려 읽기 어렵다
   (`build-week.js` 의 `FB`). 강조는 굵기가 아니라 크기 · 여백 · 괘선으로 만든다.
6. **학생용 덱에 시간 배분을 넣지 않는다.** 진행 시간표 장표, 표지의
   "오늘 120분 —" 줄, 실습 단계의 분 표기는 모두 뺀다. 시간은 수업 요약과
   발표 대본에만 둔다. (`COURSE.showTiming: false`)

## 4. 그대로 두는 것

- 영문 키커(`OBJECTIVES` `PRINCIPLE` `STRUCTURE` `COMPARE` `WORKSHOP 1` …)
- `PHASE` `WEEK` `SECTION` `NEXT WEEK` 같은 구조 라벨
- 숫자·비율·마감일, 직무 이름(UX · 서비스 · 제품 · 공간 · 그래픽 · 브랜딩)
- 운영 메모(`note`)는 강사용이므로 평소 말투 그대로 둔다

## 5. 아직 확정되지 않은 것

  PHASE 3 `완성과 발표` — PHASE 1만 교수님이 고치셨다. 나머지 두 개는 확인 필요.
- 4~15주차 본문 — 위 대응표를 아직 적용하지 않았다. 3주차만 반영돼 있다.
- 서비스디자인 · 컨셉트와 프로세스 과목 — 적용 여부 확인 필요.
