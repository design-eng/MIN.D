### 폴더 번호와 자료 번호가 한 칸 어긋나 있다 (2026-09-30 확인)

### 교수님이 직접 넣으신 사례 이미지 (2026-09-30 확인)

5주 폴더의 통합본(3.7MB)에는 교수님이 직접 넣으신 컬러 사례 이미지가 두 장
들어 있다 — 헤더 OS별 비교, 리스트와 카드의 실제 화면. 폰 프레임에 실제 같은
내용을 채우고 번호 콜아웃과 수치 요약 상자를 붙인 구성이다.
이 방식이 사례 도판의 기준이다 (`docs/문장-스타일.md` 원칙 9번).
저장소에서 만든 사례 도판은 `assets/case/` 에 둔다.

## 올릴 때 주의

**세션에서 pptx 를 Drive 에 직접 올릴 수 없다.** Drive 커넥터의 `create_file` 은
파일 내용을 base64 문자열로 요청에 실어야 하는데, 415KB 짜리 덱이면 약 55만 자가
되어 한 번에 보낼 수 없다. 도판을 다 빼고 글자만 남겨도 9만 자 수준이다.
중간에 끊긴 파일이 올라가므로 시도하지 않는다.

그래서 **완성한 pptx 는 SendUserFile 로 보내고, 교수님이 해당 폴더에 넣으신다.**
메시지에 폴더 링크를 함께 드리면 편하시다.

읽는 것은 된다. `download_file_content` 는 결과가 크면 파일로 저장되므로,
Bash 로 base64 를 디코드해 pptx 를 열어 볼 수 있다. 교수님이 고치신 자료를
확인할 때 이 경로를 쓴다.

- `build-week.js` 는 STREAM + compression 으로 저장해 파일을 3분의 1 이하로
  줄인다(글자만 있는 덱 70KB 안팎, 도판이 들어가면 그만큼 커진다).
- 흑백 규격 도판(PNG)은 32색 팔레트로 저장한다. 선화라 손실 없이 3분의 1이 된다.
  컬러 사례 도판은 팔레트를 쓰지 않는다 — 그라데이션이 뭉친다.
- 교수님이 직접 올리실 때 Google 슬라이드로 변환하면 Pretendard 조판이
  흐트러진다. pptx 그대로 두시는 편이 낫다.
